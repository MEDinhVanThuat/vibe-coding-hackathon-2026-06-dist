# AI コーディングツール活用ガイド

> 言語: [English](ai-tools-guide.md) | **日本語** | [Tiếng Việt](ai-tools-guide.vi.md)

このハッカソンでは AI コーディングツールの利用は**自由**かつ**推奨**されます。指定のツールはありません。指定のワークフローもありません。普段使っているもの、これを機に試したいものを使ってください。

## 利用可能なツール（例）

どれを使っても OK です。

| ツール | 形態 | 主な特徴 |
|---|---|---|
| Claude Code | CLI / IDE 連携 | エージェント志向、サブエージェント並列、長時間タスク |
| GitHub Copilot | IDE inline + Chat | 補完中心、PR 作成支援 |
| Cursor | IDE | 補完 + 会話、composer モード |
| Windsurf | IDE | エージェント機能、ファイル操作の自動化 |
| Aider | CLI | git ワークフロー統合 |
| Gemini Code Assist | IDE | 大コンテキスト、Google エコシステム |
| ChatGPT / Claude.ai | Web | 会話のみ、コードは copy/paste |

ツールの違いは実務のチームでも普通に存在します。あなたの仕事を助けてくれるものを持ち込んでください。

## 実用パターン

AI コーディングツールでうまくいきやすい習慣をいくつか挙げます。ルールではなく、タスクに応じて取捨選択してください。

### タスクの複雑さに合わせた手数で取り組む

計画やレビューにかける手数はタスクによって変えていい。

- 1 行のラベル変更にはガッツリした計画は要らない
- 複数ファイルにまたがる機能追加にはあった方が良い

軽いタスクに過剰に計画を組むと時間を食う。重いタスクを計画なしで突っ込むと後から追わなきゃいけないバグを生む。

### コンテキストを与える、与え忘れない

ほとんどの AI ツールは初期状態では repo のごく一部しか見ていない。変更を依頼する前に、関係するファイルを明示的に指示してください。スキーマ、編集対象のページ、関連 API ルートなど。

短いプロンプト + 正しいファイル添付 のほうが、長いプロンプト + 文脈ゼロ よりだいたい良い結果になる。

### AI の出力を実行する前に読む

「コンパイル通った」と「動く」は違う。「動いた 1 回」と「エッジケースを処理している」は違う。diff にざっと目を通す。明らかなケースで動かす。明らかでないケースを 1 つ試す。

### 何から手を付け、何を後回しにするか決める

6 ストーリーで 1.5 時間。全部を綺麗に仕上げるのはおそらく無理。ストーリーを読み、順番を決め、何を見送るかを決め、その理由を commit message や PR 本文に書き残してください。

理由の方が、機能の数より価値があります。

### AI が同じ失敗を繰り返したら、立ち止まる

3 回続けて間違った出力が返ってきたら、それはシグナル。プロンプトにコンテキストが足りないか、タスクの定義が曖昧か、AI に必要な情報が届いていないかのどれか。一歩引いて整理するか、自分で書く。

## 当日の心構え

- **完璧を目指さない**: 6 ストーリー全部終わらなくて OK。どこに集中するかはあなたの判断。
- **AI を信頼しすぎない**: 動作確認は自分でする。「AI ができたと言った」と「自分で動くことを確認した」は違う。
- **AI に丸投げしすぎない**: 重要な判断（着手順、設計、最終的な品質）は自分で。
- **詰まったら立ち止まる**: 同じプロンプトで 3 回失敗したら、アプローチを変えるか、自分で書く。

楽しんでください。
